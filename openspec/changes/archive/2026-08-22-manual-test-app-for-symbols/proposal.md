## Why

Stylesheets (`*.oss`) define vector symbols (`SYMBOL` blocks with `POLYGON`/`RECTANGLE`/`CIRCLE` primitives). Symbol definitions are now increasingly generated by AI, which can produce malformed geometry, wrong colors, overlapping or invisible primitives, and off-canvas shapes.

Today there is no way to review a stylesheet's symbols in isolation: they are only visible while rendering a full map, where a broken symbol hides among thousands of others. A quick visual scan of every symbol of a stylesheet on a plain background makes correctness obvious.

## What Changes

1. **Symbol enumeration API** in `libosmscout-map`: add a public accessor to `StyleConfig` that returns the names of all registered symbols (the `symbols` map is currently private, only `GetSymbol(name)` and `RegisterSymbol` are exposed).

2. **New manual test application `SymbolsAll`** (in `Demos/`, following the `TextMetricsAll`/`DrawMapAll` pattern):
   - CLI: `--stylesheet <file.oss>` (required), `--output <dir>`, `--dpi`, `--size <n>` (square canvas in px), `--backend cairo|svg|all`, `--ost <file>` (optional type definition file; defaults to a sibling `.ost` of the stylesheet or `map.ost` next to it), `--list` (print symbol names only).
   - Loads the stylesheet via `TypeConfig` (from the `.ost`) + `StyleConfig::Load`.
   - Renders every registered symbol standalone, centered, via `SymbolRendererCairo` (bitmap PNG) and/or `SymbolRendererSVG` (SVG file), using the existing `SymbolRenderer::Render(projection, symbol, mapCenter, scaleFactor)` pipeline with a `MercatorProjection`.
   - Writes one image per symbol into the output directory (`<symbol-name>.png` / `<symbol-name>.svg`).
   - Optional `--sheet` mode: single contact-sheet image (PNG grid with symbol names) per backend for fast scanning of many symbols.
   - Prints a per-symbol result line, returns non-zero exit code if a stylesheet fails to load or any render/write fails.

3. No changes to any render backend; only consumers of existing `SymbolRenderer` implementations.

## Capabilities

### New Capabilities
- `symbol-scan-tool`: The `SymbolsAll` demo tool that enumerates every symbol of a stylesheet and renders each standalone to an image via the Cairo and/or SVG backend, so all symbols can be visually scanned for correctness (e.g. AI-generated ones). Covers the `StyleConfig` symbol enumeration API, the CLI contract, per-symbol output, contact sheet mode, and failure reporting.

## Impact

- **New file**: `Demos/src/SymbolsAll.cpp`
- **Modified files**: `libosmscout-map/include/osmscoutmap/StyleConfig.h` (public symbol enumeration accessor), `libosmscout-map/src/osmscoutmap/StyleConfig.cpp`, `Demos/CMakeLists.txt`, `Demos/meson.build`
- **Dependencies**: No new external dependencies. Uses existing Cairo (`cairo_surface_write_to_png`) and SVG (`SymbolRendererSVG`) capabilities; backends are optional at build time (`HAVE_OSMSCOUT_MAP_*` guards, like `TextMetricsAll`).
- **API**: One additive public accessor on `StyleConfig`; no behavioral changes to existing rendering.
