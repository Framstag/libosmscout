# Tasks

## 1. Worker shutdown and failure handling (spec: async-worker-lifetime)

- [x] 1.1 In `libosmscout/include/osmscout/async/AsyncWorker.h` and `libosmscout/src/osmscout/async/AsyncWorker.cpp`, add a public, idempotent `Stop()` that marks the worker as stopped, stops the queue and drops the jobs that have not started, asks the jobs in flight to stop through their `Breaker`, and then waits for the job that is running (a worker that could not be joined is disposed of by the destructor). Have `~AsyncWorker()` call it, and document on the method that a derived class whose jobs use its members must call it before those members are destroyed. Verify: the library builds and the async tests pass.
- [x] 1.2 In the same files, make a failing job harmless: catch exceptions where the job's promise lives (`Async<T>`) and log the failure, resolving the promise with a default-constructed result, and add a backstop catch in `AsyncWorker::Loop()` so no job can escape the worker thread. Verify: the library builds and `AsyncProcessingTest` passes.
- [x] 1.3 Call `Stop()` as the first statement of the destructors of the workers whose jobs use their members: `MapManager` (`libosmscout-client/include/osmscoutclient/MapManager.h`, `MapManager.cpp`), `DBThread` (`libosmscout-client/src/osmscoutclient/DBThread.cpp`), `MapDownloadService` (`libosmscout-client/src/osmscoutclient/MapDownloadService.cpp`) and `POILookupModule` (`libosmscout-client/src/osmscoutclient/POILookupModule.cpp`), each with a comment naming the reason. Verify: the client library builds and the existing client tests pass.

## 2. Worker tests (spec: async-worker-lifetime)

- [x] 2.1 In `Tests/src/AsyncWorkerTest.cpp`, add a test worker whose member records its destruction into state owned by the test, and a job that reports whether it ran after that: assert that destroying the worker waits for the running job and that the job never observes destroyed members. Verify: the test passes, and it fails when the worker is not stopped before its members are destroyed (checked in that direction while developing).
- [x] 2.2 Extend the test with the shutdown cases: a job that was queued when the worker was destroyed does not run and its caller is released (cancelled, and a blocking wait on it does not hang), a job that observes the stop request ends at its next check so that the teardown does not wait for it, a job submitted after the shutdown is cancelled and not queued, the shutdown can be called twice, and a worker that deletes itself from its own job does not deadlock. Verify: the test passes, and the discard case passes repeatedly in both build systems (the Meson configuration reproduced the interleaving that a stop-then-break order allows).
- [x] 2.3 Extend the test with the failure cases: a job that throws is logged and the process keeps running, a later job still runs and its result reaches its caller, and the caller of the failed job is released with the default value instead of waiting forever. Verify: the test passes.
- [x] 2.4 Add a case whose job sleeps and then writes into heap buffers of its owner, so that a build which gets the shutdown order wrong is reported by a sanitizer instead of silently passing (the `MemberGuard` cases read only state owned by the test and therefore cannot catch it). Verify: the case passes, and with the `Stop()` call removed from that worker's destructor the sanitizer build reports `heap-use-after-free` in the job.
