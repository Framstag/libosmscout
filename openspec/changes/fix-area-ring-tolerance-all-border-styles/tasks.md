## 2. The per-ring tolerance

- [x] 2.1 Add the shared helper that returns the visibility tolerance of a ring in pixels as the maximum over the resolved border styles of half the width plus the display offset, converted with `projection.ConvertWidthToPixel`, plus the offset projected with the projection's pixel size (design D1). It is an exported free function `osmscout::GetAreaRingTolerancePixel` in `libosmscout-map` (`include/osmscoutmap/AreaBorderReach.h`, `src/osmscoutmap/AreaBorderReach.cpp`, registered in both build systems), not a `MapPainter` member, because `MapPainterOpenGL` is not a `MapPainter` and has to read the same expression. Verify: the helper is the only place in `libosmscout-map/` and `libosmscout-map-opengl/` that converts an area border width, offset or display offset for a visibility decision, and both builds compile the header.
- [x] 2.2 Use the helper in `MapPainter::PrepareAreaRing` in place of the front-style rule (`MapPainter.cpp:1329-1339`) and verify: `xvfb-run ctest -j 2 --output-on-failure -R "MapPainter|Area|Label"` passes, and the new tolerance is never smaller than the previous expression (a maximum over the resolved styles covers the front style's half width, and the front style contributed nothing at all when it carried an offset), so no ring the previous decision kept can be dropped. The prepared-entry count of the Dortmund view is not re-measured: a wider tolerance intentionally reaches further at the viewport edge (spec: `map-painter-area-culling` - Prepared entries, clipping geometry, orders and rendered output are unchanged), and no shipped stylesheet declares an area border offset, so the difference is confined to rings whose front style is narrower than another slot of the same ring (spec: `map-painter-area-culling` - A ring's visibility tolerance covers every border style the ring resolves).
- [x] 2.3 Extend the headless painter test (`Tests/src/MapPainterAreaVisibilityCullTest.cpp`) with the cases of the new requirement: a ring whose widest drawn border is not the style the decision reads first is kept, a ring whose border is drawn at an offset and reaches the view is kept, a ring whose drawn borders do not reach the view contributes no prepared geometry, and a ring without an offset border keeps its tolerance (spec: same requirement). Verify: each of the two positive cases fails when the tolerance is reduced to the front style's half width, and the tests are registered in both build systems.
