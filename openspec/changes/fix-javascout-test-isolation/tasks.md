## 2. Client ownership in the test classes

The isolation guarantee is delivered by releasing the client however the test ends. A process boundary per
test class was measured and rejected: `verification.md` records 7 failing runs in 10 with it, against 1 in
10 without, caused by an unrelated defect in `OSMScoutClientBasemapConfigTest`.

- [x] 2.1 Replace the availability probe so it releases whatever it builds and is never handed to an assertion, in all twelve classes that call `new OSMScoutClient()` - verify: `grep -rn 'new OSMScoutClient()' JavaScout/src/test/java` shows only the probe helper, and `mvn test` without `-Dnative.lib.dir` still reports the affected classes as skipped with the missing-library reason. (spec: javascout-test-run - A class that cannot obtain a client reports its tests as skipped)
- [x] 2.2 Release the client in an unwind path (`@AfterEach` or `try`/`finally`) in `OSMScoutClientGetRoadAtTest`, `OSMScoutClientInstructionDistanceTest`, `SearchReproTest`, `OSMScoutClientSearchQualityTest`, `OSMScoutClientAdminRegionScopeTest`, `OSMScoutClientDataCacheBudgetTest`, `OSMScoutClientDataCacheSizeTest`, `OSMScoutClientFavoriteOrderingTest`, `OSMScoutClientBasemapConfigTest`, `FavLocationDialogOrderingTest` and `OSMScoutClientNavigationLiveTest` - verify: the fault injection of 1.3, re-run with one test deliberately failing inside the class (then removed), leaves every later test in the same class able to build its client. (spec: javascout-test-run - A failing test releases the client it obtained)
- [x] 2.3 Give the classes that build several clients (`OSMScoutClientPoiSearchTest`, `OSMScoutClientNavigationLiveTest`, `OSMScoutClientGetRoadAtTest`, `OSMScoutClientBasemapConfigTest`) a release around each individual client - verify: the same fault injection with a failure in a test that builds a second client. (spec: javascout-test-run - A skipped test releases the client it obtained)
- [x] 2.4 Delete the retry loops `openFixtureClient` and `openLookupClient` in `OSMScoutClientPoiSearchTest` now that a leak cannot hide a client - verify: the POI search tests pass repeatedly (three consecutive suite runs) with the retry loops gone.
